# Native terminal session manager

## Current support

Implemented on Windows x64 with Windows Terminal and local non-elevated PowerShell. Session records survive closure. Clicking a confirmed closed window opens one fresh shell/window attached to the SAME session; concurrent clicks are single-flight. Unknown ownership, an uncertain prior launch or focus denial does not trigger reopen. Window generations and exact registered shell identities persist and restore without command replay.

User-created or moved tabs join through the explicit **Register this terminal** UI action and shipped PowerShell registration script. A confirmed re-registration transfers an existing shell/tab identity between sessions without deleting the source session. Registered-member enumeration is supported; automatic discovery of unintegrated tabs or tab moves is NOT available. Unsafe automatic WT appends remain disabled after a real misrouting failure. This does not satisfy the original automatic two-window/three-tab launch acceptance.

Use the destination session's registration action, select the actual PowerShell version, and run its short-lived generated command in the selected interactive tab. If WT suppresses titles, manually Rename Tab to the displayed challenge marker first. Refresh registered members afterward. No global profile installation or user settings mutation is performed. See README.md for instructions and tmp/report-a-window-lifecycle-adoption.md for evidence limits. Real GUI drag, Explorer/installed lifecycle and clean-machine acceptance remain unproven. Other OS/terminal/shell targets below are future scope, not implemented adapters.

## Product model

An Electron app organizes tasks while the user's native terminal app runs the commands. No embedded terminal.

One manager session owns several terminal tabs, usually in one dedicated native window:

```text
Session: Fix checkout | folder: /projects/shop
  Native terminal window
    Tab: Claude agent
    Tab: Codex agent
    Tab: Bash commands

Session: Update documentation | folder: /projects/docs
  Another native terminal window
    Tab: Pi agent
    Tab: Preview server
```

Sessions have stable IDs. A folder is a default working directory, not an identity: several sessions can use the same folder. Each tab has its own ID, registered shell, and process status.

Clicking a session focuses a confirmed live native window, or reopens a confirmed closed window on the same session UUID with a fresh tab/operation/generation. Never replay commands or treat unknown ownership as closure. Clicking a child focuses the session window; select the specific tab in Windows Terminal. Specific-tab activation/persistence is unsupported.

## Feasibility and constraints

This is feasible for a defined list of supported terminal apps, not through one universal terminal API. Each adapter must prove window creation, adding tabs to the correct window, target identification, and focus behavior.

Native terminals own rendering, shortcuts, tabs, and splits. The manager does not embed their windows. OS focus restrictions still apply, especially on Wayland. Unsupported controls must be visible in the UI, not silently emulated with keystrokes.

Start with manager-created windows. Explicit authenticated shell registration is implemented for manual/moved PowerShell tabs in a confirmed managed destination. Automatic discovery, move notifications and arbitrary existing-window attachment require additional APIs and are deferred. Splits need one registration per shell and remain unsupported.

## Tech stack

| Part | Choice |
| --- | --- |
| Desktop app | Electron, TypeScript, Electron Forge with Vite |
| Interface | React, Zustand, CSS variables |
| Native terminal control | Per-terminal adapters using documented CLI, IPC, or OS APIs |
| Shell registration | Self-contained .NET Windows helper plus explicit PowerShell integration; Bash/Zsh deferred |
| Local communication | User-restricted named pipe on Windows or Unix socket, authenticated per launch |
| Process monitoring | Platform-specific process enumeration plus shell events |
| Storage | SQLite with better-sqlite3 and migrations |
| Tests | Vitest, Playwright for manager UI, native-terminal integration tests |

No xterm.js or node-pty. No cloud service required. Package native dependencies for each OS and architecture.

## Launch and tracking

1. Create a session ID and tab ID, then persist their intended association.
2. Create a new dedicated window, or replace a confirmed closed window on the same saved session. Automatic append is disabled; extra native tabs require manual creation and explicit registration.
3. Start the configured shell through a registration helper. Report shell PID, process start time, working directory, and session/tab IDs.
4. Record native window/tab identifiers when available. If launch fails, show an error rather than create duplicate tabs on automatic retries.
5. Track configured agents beneath each registered shell. Do not use the terminal application's process tree, window titles, or folder alone to assign processes.

Process rules match executable identity and optional arguments, including launchers such as Node-based CLIs. Defaults cover pi, Claude, Codex, and OpenCode; users can edit the list.

Validate process start times to avoid PID reuse. Detached processes, terminal multiplexers, WSL, SSH, and containers need additional integration. Do not promise reliable tracking there in v1.

## File manager context menu

Add an opt-in **Open session in Shellfox** action in both places:

- Right-click a folder: use the selected folder as the CWD.
- Right-click empty space inside a folder: use the displayed folder as the CWD.

The action invokes `shellfox --new-session --cwd <absolute-path>`. Start the manager if needed; otherwise forward the request to its existing instance through Electron's single-instance handling. Each invocation creates a new session, even if another session uses that folder, and opens one native terminal window with an initial shell tab there.

Validate that the path is an accessible local directory. Preserve spaces and Unicode, pass arguments safely, and never interpret the folder name as a command. Show launch failures in the session with a Retry action.

Platform integration needs separate implementations:

| Platform | Integration |
| --- | --- |
| Windows Explorer | Per-user shell registrations for folder items and directory backgrounds. A basic verb may appear under Windows 11's Show more options; top-level placement needs a separate modern shell integration. |
| macOS Finder | Prototype a Finder extension or service. Selected-folder actions and empty-space actions are not interchangeable; verify both before claiming support. |
| Linux | Use file-manager-specific actions or extensions. Target Ubuntu's Nautilus first; confirm the file manager used in the intended Omarchy setup. |

Provide install/remove controls in settings and remove registrations on uninstall. Ship integrations only after testing both click locations; document unsupported cases. Virtual folders and remote locations are outside v1.

## Status rules

- **Running:** at least one configured process is alive in a registered tab.
- **Waiting:** tracking is healthy and no configured process is alive.
- **Error:** a sticky launch/control failure. Arbitrary command exit codes are not detected in this MVP.
- **Unknown:** registration or monitoring is unavailable.
- **Settled:** the user marked the session complete.

An agent waiting for input is still running under these rules. Optional agent hooks can refine this later. Ordinary Bash commands do not affect the badge unless covered by a rule or optional all-command tracking. Explain this in settings.

Show individual tab states and session counts, such as "2 agents running, 1 tab waiting". Proposed aggregate precedence: error, running, unknown, waiting. Settled is a manual override, not process termination; warn when settling a session with active or unknown tabs and continue tracking them.

Sidebar order: waiting, error, running, unknown, settled. Keep stable ordering within each group.

## Interface and persistence

- Sidebar shows session title, folder, status, and expandable child tabs.
- Main panel shows session details, focus/reopen, registered membership refresh and explicit PowerShell registration. Manager-driven append, close/stop and specific-tab activation are disabled. Terminal content remains in the native app.
- Dark theme, pink default accent, configurable colors, terminal adapter, shell profile, and process rules.
- Settled sessions appear dimmed in collapsible history with title/folder search, filters, and pagination.
- Persist session/tab associations and terminal identifiers. On manager restart, validate live targets and reconnect where supported. Distinguish confirmed closure from unavailable ownership. Keep the session after either, fence stale generation/member events, and reopen only on an explicit user click after confirmed closure. Never imply processes/commands were restored.
- Closing the manager leaves native terminals running. Closing terminals or stopping agents requires a separate explicit action.
- Keep Node integration off in the renderer and expose only validated operations through preload. Pass launch arguments without unsafe shell-string concatenation.

## Delivery steps

1. **Validate the preferred terminal.** Choose the user's actual terminal apps. Prove two session windows with three tabs each, correct tab placement, focus, and independent process tracking. This is the go/no-go test before building the full UI.
2. **Build the manager.** Add sessions, tab records, launch/focus actions, settings, and failure handling. Implement the new-session CLI and single-instance routing, then add file-manager context menus. Test folder-item and empty-space clicks with the app open and closed, including paths with spaces and Unicode. Switching live sessions must never restart commands. Explicit click-to-reopen after confirmed window closure creates only a fresh shell, not old commands.
3. **Add status and history.** Implement configurable process rules, aggregation, settling, SQLite persistence, and restart reconciliation. Test two sessions sharing one folder.
4. **Expand platform support.** Add tested adapters for Windows, macOS, Ubuntu, and the intended Omarchy environment. Publish a capability matrix and prepare signed releases.

## Defer

Arbitrary terminal embedding, universal tab control, automatic attachment of existing terminals, remote tracking, cloud sync, transcript capture, and agent-specific input detection.
