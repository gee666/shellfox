# Shared terminal runtime

This is the local terminal owner for Rust desktop and headless hosts. It has no GPUI, network, SQLite, or mobile binding dependency. The metadata host registers a validated session/tab/generation before `Runtime::start`. Only `Phase::Closed` permits `Host::terminal_stopped` and a pending metadata close commit.

One dedicated thread creates and owns `shellfox_ghostty_vt::Terminal` and `shellfox_terminal::PtySession`. It feeds each PTY chunk once and sends the parser's query replies once. Views never write parser replies or encode terminal-dependent input themselves. Windows uses the terminal crate's contained supervisor/Job launch. Unix launch remains refused until an equally safe owned-process boundary exists. There is no numeric-PID fallback.

## Host boundary

`Runtime::start(Identity, PtyConfig)` returns after owner-thread creation. PTY startup completes asynchronously through `Event::Started`. A failed spawn may retain resources. Keep the runtime until `phase() == Phase::Closed`, even after `Started(Err(...))`. A synchronous start error means no PTY was created.

The host supplies `PtyConfig` with separate `cwd` and `isolation_root`, explicit environment policy, and a trusted absolute supervisor executable. That executable must call `shellfox_terminal::supervisor_entry()` before argument handling, GUI initialization or thread creation. This is a private local executable contract, not a remotely selectable program path.

`Runtime::try_send(Request { id, command })` uses a bounded command queue. `SubmitError::Full` returns the unsent request for caller retry. Input over 64 KiB is rejected before enqueueing. `Runtime::start` uses `GridLimits::default()`, at most 262144 cells, which covers normal high-DPI and ultrawide grids. `Runtime::start_with_limits` accepts `GridLimits::new(max_cells)` up to the hard limit of 1048576 cells. Each PTY axis is limited to 32767. Invalid resizes return validation errors before touching either parser or PTY, without closing the shell.

The checked Ghostty wrapper enforces a 16 MiB aggregate UTF-8 text bound before copying cell strings; runtime frame publication checks that bound again. Attribute storage is bounded by the configured cell count. Only one frame waits in the coalesced slot. Runtime consumers must also handle bounded event-channel backpressure instead of assuming replies arrive synchronously.

Commands include:

- `Claim { controller, takeover }`, producing a fresh `Lease` on every successful attachment.
- Owner-encoded `Key`, `Paste`, and `Mouse`, plus explicit local-host `RawInput`.
- Ordered `Resize`, `Colors`, `Scroll`, `Selection`, `Copy`, `Hyperlink`, and `MouseTracking`.
- `Screen`, `Replay`, `Ack`, `RecoverAnsi`, `Close`, and host-authorized `RetryClose`.

Read-only subscriptions are separate from control. `Observe { viewer, after }` returns `Response::Observed(ObserverLease)` without claiming or taking control. `ObserverReplay`, `ObserverAck`, `ObserverRecover` and `Unobserve` accept only that observer identity. Initial `after: None` waits for explicit replay/recovery. A supplied resume cursor is validated against the shared journal, never silently replaced by its retained tail. Reattaching a viewer advances its observer epoch.

At most 16 observers share the single 1 MiB journal. Each stores at most 128 KiB/256 chunks of pending credit metadata, not another output ring or parser. Observer output, replay-loss and exit events carry the observer lease. ACKs affect only that lease. Controller and observer-first rounds alternate; observers rotate fairly within a round. Neither path advances live credit on event-channel queue failure. Already-queued events for detached/stale epochs must be ignored by the host's view router.

The host assigns viewer/controller identities and enforces authenticated view permissions before constructing commands. These local Rust structs are not an authentication protocol. An observer identity cannot authorize input or resize, and a read-only network attachment must never be upgraded by forwarding a client-supplied control claim.

Successful Key, Paste, Mouse and RawInput commands return `Response::Input(InputReceipt { accepted_bytes, kind })`. Mechanical kinds expose only key action/committed-text presence, paste nonemptiness, mouse action/button state, or Raw. There is no raw text, password, coordinate or recaptured UI context. Ignored encodings still return `Input` with zero bytes, not `Applied` or a missing receipt. Zero skips both the pre-write observer and the actual writer. Positive bytes mean the whole encoded write completed, not that the shell read or executed it. Invalid/partial/failed writes do not return a positive receipt. Encoded overhead is checked against 64 KiB before writing.

The UI/service keeps its admission-captured settlement token and semantic hint by request ID. A receipt only gates the existing policy; it never creates authority or recaptures intent. Key releases and passive mouse encodings may still require semantic handling even when a protocol emits bytes.

The renderer may copy selection text to the OS clipboard only after user intent. A hyperlink reply is untrusted process metadata, not authorization to open a URI. This crate does not touch either OS service.

## Atomic V2 recovery and canonical layout

V2 uses additive `ObserverRecoverStamped`, returning `Response::Recovery(StampedRecovery)` with bytes, capability, last delivery sequence, actual columns/rows, canonical layout revision and an opaque `RecoveryId`, captured in one owner barrier. Existing `Ansi`/V1 recovery is unchanged. Layout revision starts at one and changes only when canonical dimensions actually change, including a PTY or passive external resize. Byte counters, theme changes, frame versions and duplicate resizes never manufacture revisions.

After opt-in, `ObserverLayout` is ordered behind all bytes at its delivery boundary and blocks later bytes. It is a notification, not a resize grant. The client must consume a NEW full stamped recovery; only `ObserverLayoutAck` matching that latest opaque ID, observer, sequence and revision opens the gate. Ordinary ACK or a standalone notification/resize acknowledgement cannot do so. Server code stores the private Runtime ID against its wire recovery UUID and calls this ACK only after validated client consumption. A repeated same-sequence/same-layout recovery gets a new opaque ID so an old ACK cannot unlock it.

The shared geometry journal is bounded to 64 changes. A lagging observer outside its range gets explicit recovery-required notification, not skipped geometry. Canonical/parser output order is the boundary, not a claim about bytes concurrently generated by the child before the OS resize. These commands grant no new layout authority or raw-process cleanup proof.

## Blink reset parity limit

The shipped DOM renderer uses a one-second step-end blink with 50% duty, and resets when its cursor-row span is replaced. Output sequence, presentation version and cell-content equality cannot prove that replacement. No `row_paint_revision` is fabricated from them here.

Ghostty's public `render.h` exposes opaque row identity and row/global dirty invalidation, not a paint counter or xterm DOM refresh event. Render-state update consumes terminal/screen dirty state; dirty consumption clears the shared cache flags. The wrapper's canonical, presentation and cursor reads all use that shared cache. A future native row-invalidation revision would need one central wrapper collector around every update, immutable fan-out to views and explicit coverage for history rows. A second independent dirty reader is not safe.

Even such a revision would describe Ghostty invalidation, not prove identical xterm span-replacement semantics. Exact source-driven blink-reset parity therefore remains a gap. Native consumers can honestly implement 500 ms phases and their known local focus/selection redraw resets without resetting on unrelated output or generic view-version changes.

## Query ownership

The host owns every reply produced by Ghostty's `WRITE_PTY` callback, including live OSC 4 palette and OSC 10/11/12 foreground/background/cursor queries. Cursor color falls back to the authoritative foreground when not explicitly configured. These are not live-view/browser-owned queries. Real-library tests verify fragmented BEL/ST queries, exact configured RGB replies, one-time draining and no replies during rendering.

Other supported callback families include device attributes/status, DECRQM, DECRQSS, XTGETTCAP known capabilities, Kitty keyboard queries, XTVERSION, visibility reports and Kitty OSC 21 color queries. Optional geometry, color-scheme, enquiry, clipboard and program-status callbacks are not currently configured. Their absence is not permission for a UI parser to answer on the host's behalf. ConPTY may itself intercept some queries before their bytes reach Ghostty.

Raw byte clients must suppress their own automatic query replies. They must not remove response-looking bytes from typed paste or from bracketed-paste regions. A raw unbracketed input stream cannot distinguish intentionally pasted reply bytes from an identical automatic terminal response; do not claim lossless paste plus blanket response filtering without input provenance.

## Frames and byte delivery

`Command::Presentation { view, action }` addresses either `PresentationLease::Controller(Lease)` or `PresentationLease::Observer(ObserverLease)`. Frame, scroll, follow-tail, selection, copy and hyperlink actions operate on that view only. They never move the authoritative viewport, install a host selection, alter input modes, drain replies or parse a second byte stream. Read-only observer actions validate only the observer lease and never claim control or write/resize the PTY.

`PresentationAction::Frame { focused }` returns `Response::Presentation(Arc<ViewFrame>)`. Its `screen: Arc<ScreenFrame>`, row metadata, projected cursor visual and history bounds are owned immutable data. The view-local `version` changes for selection/scroll/focus even at the same output sequence. Unchanged requests reuse the same frame Arc; focus-only changes reuse cells and row metadata. Inactive cursors use `CursorVisual::for_focus(false)`, without changing terminal modes.

`ViewFrame.selection` carries the wrapper's checked `Option<PresentationSelection>`, not endpoints inferred from selected-cell masks. Anchor/focus are inclusive physical cell positions in retained primary/alternate history. Row zero is the oldest retained row, not an output sequence or durable row ID. Range preserves direction and rectangle diagonals; Word/Line/All are normalized forward. `view_top_row` and `total_rows` match the frame. Offscreen endpoints remain absolute. An unset or pruned endpoint is `None`; the producer does not distinguish those cases, and consumers must not invent or clamp an endpoint. AT/text mapping must follow actual published `Cell.text` boundaries and widths, including zero-width wide-tail cells. Do not concatenate a row and re-run Unicode grapheme segmentation across VT cells: with mode 2027 off, woman+ZWJ and laptop may occupy separate rendered clusters, while mode 2027 on can store one cluster. A combining sequence inside a cell remains that cell's text. This supplies selection facts, not a claim of complete native accessibility text-range parity.

AT coordinate mutations use `PresentationAction::SelectionAtVersion { version, selection }`, carrying the original SemanticTree-sampled frame version unchanged. The owner checks current lease, cached version, source revision and sampled bounds before calling the native selector. Output/reflow can invalidate a cache before another frame is requested, so cached version equality alone is insufficient. Local scroll/selection/focus changes invalidate old samples too. `StalePresentation` rejects without mutation or clamping; the consumer drops the action and requests a fresh semantic frame, never retries old coordinates against new state. Existing caller SemanticTree/identity/view stamps remain required. Ordinary pointer gestures keep the unguarded `Selection` action. This queue fence alone does not establish complete AT mutation parity.

At most 17 native view handles exist, one controller and 16 observers. Lease replacement/detach frees old handles before allocating replacements. Meaningful key/paste/raw input follows only the existing controller view's tail. Source changes invalidate cached frames, but no grid is copied until a consumer requests one. Default headless operation creates no presentation view or cell snapshot.

`take_screen()` remains an owned `ScreenFrame` compatibility path for the current controller. Its first call or a legacy `Screen` command opts into one coalesced controller snapshot; callers migrating to typed frames should stop polling it to avoid the compatibility clone. Every cell owns its UTF-8 text. There is no unbounded frame queue.

A successful claim must initialize delivery with `Replay { after }` or explicit recovery. Replay history is bounded to 1 MiB and 512 chunks. Individual chunks are at most 4096 bytes. Unacknowledged credit is bounded to 128 KiB and 256 chunks. ACKs cannot decrease, exceed the delivered sequence, or use an old epoch. A takeover fences input, ACKs and delivery from the previous lease.

A native view does not feed replay bytes into another parser. It can consume replay/output as sequence delivery notifications, accept its immutable frame, then ACK the lesser of that frame sequence and highest delivered byte sequence. Merely requesting or receiving a frame does not ACK anything. The private presentation version is a repaint key, not a byte-credit sequence. A frame-only read-only client can attach with `Observe { after: None, .. }` and use typed presentation requests without enabling raw byte delivery.

`ReplayLost` reports a gap once per claim/recovery. The runtime never skips that gap silently. `RecoverAnsi` returns `VisibleScreen` ANSI for the visible cells and cursor, plus a sequence barrier. It does not restore scrollback, alternate-buffer identity or application input modes. Use it only when the client explicitly accepts visible-screen recovery.

`Recover { capability: FormattedActiveBufferV1, .. }` explicitly requests Ghostty's public VT formatter, supported extras, active-buffer history and exact unfinished UTF-8/VT continuation. Twelve recovery regressions cover live continuation, resize, active alternate buffer, pending wrap, styles and query-reply preservation. The inactive buffer, saved cursor and full keyboard stack are not recoverable through this contract, so `FullState` is not advertised. A full old-client-compatible state serializer remains a parity gap. Neither limited capability may silently replace the existing Node/RN recovery protocol. Optional formatted recovery refusal returns `Unsupported` without terminating the PTY.

Ghostty binary snapshots are never returned by this API. Recovery establishes new delivery credit only after its exact barrier sequence is acknowledged.

## Close and failures

Normal lifecycle is `Starting -> Active -> Draining -> Closed`. Root exit and `Close` stop input, retain the PTY reader, and drain final bytes through EOF before final shutdown. A queued resize drains the bounded reader queue under the old dimensions first. OS bytes racing the actual resize have no stronger ordering guarantee.

Parser poison, read/write failure or failed cleanup moves the runtime to draining cleanup. Failed cleanup keeps the owned PTY in its owner thread and retries. `RetryClose` does not require a view lease because cleanup is host authority. Explicit UI close should wait for `Closed` and must retain the prepared metadata-close token on failure.

`Phase::Closed` means process/controller cleanup is confirmed. It is distinct from `Exited { lease, last_sequence }`, which follows delivery of final output to that lease. Views must ignore stale-lease output, replay-loss and exit events. A slow or detached viewer can delay exit delivery but cannot delay process cleanup.

Dropping the runtime handle is nonblocking. It requests cleanup through a separate atomic flag even if command/event queues are full. The dedicated thread remains responsible for cleanup. It never reports confirmed cleanup on behalf of an outstanding owner.

## Passive external byte sources

`Runtime::start_external(identity, ExternalConfig)` creates its one parser and confirms readiness before returning. It returns `ExternalStartError`, distinguishing proven `BeforeThread` validation/admission/spawn failure from `OwnerUnconfirmed` readiness timeout/channel failure. `take_owner()` yields the original cancellable startup controller exactly once; it exposes no source capability. Keep the reserved run/controller until nonblocking `poll_closed()` consumes the original JoinHandle proof. Phase/timeout alone is not closure proof. Cleanup slots are reserved before parser-thread creation, bounded to 64. Handoff stores the original handle in a reachable reserved record before sending a unit wakeup; Full/disconnected wakeups cannot lose it. `poll_external_cleanup()` supplies typed retry/pending reporting even if notification failed. Reserve the immutable identity/generation and take `take_source()` exactly once before launching the raw target. Keep this parser with the run from its first output, including while no UI is attached. Show only observes that existing state. Never construct a new terminal from a truncated raw replay tail, and never normalize/redecode stdout/stderr before this byte parser.

`ExternalChunk` carries one global `SourceSequence`, `ExternalStream::Stdout`/`Stderr` and nonempty raw bytes up to 32768 bytes, in the original merged reader-queue order. Eight bounded chunks may wait. `Full` returns the exact chunk without advancing its sequence; retain it and backpressure the raw pipe until retry succeeds. The Vec allocation capacity is bounded too. No dropping, renumbering, invisible lossy Reset or new upstream parser/PTY is allowed.

The presentation replay journal may segment display output into 4096-byte delivery chunks. `external_status()` explicitly reports typed source sequence, stream, optional `delivery: DeliveryRange` for the latest raw chunk, cumulative `last_delivery_sequence`, and optional `finish_delivery` for final decoder flush. A raw chunk producing no display bytes has `delivery: None` without losing or remapping its source sequence; frame/ACK sequences remain delivery sequences. Source order is not silently remapped. Default `RawBytes` policy feeds raw bytes unchanged. Automation selects `start_external_with_policy(..., LegacyAutomationV1)` from run startup: independent stdout/stderr UTF-8 transport decoders, per-write `CR?LF -> CRLF`, then ONE stdout-end + stderr-end concatenation/normalization at final close, not per-stream EOF. This is not a second screen parser. Raw RPC bytes/global source sequence remain unchanged. Differential fixtures check the real Node StringDecoder behavior, including malformed-prefix buffering and all 65536 interleaved byte pairs.

`try_finish(last_source_sequence)` follows every accepted chunk and both EOFs. The owner drains those messages and final decoder flush in order before source-finished notification. `finished` ends only the source; `closed` stays false while the canonical parser serves late Observe/scroll/copy/Recover/resize. Only explicit `request_external_close()` after independent raw cleanup, followed by `poll_external_closed()` original join proof, closes it. Dropping the source without Finish marks it failed, not successfully completed. The consuming producer-only `ExternalSource::abort(reason)` records typed identity/reason/last-queued intent and drops that actual sole sender. The parser first drains accepted FIFO data, then observes disconnection and marks failure; abort intent itself is neither processed failure nor EOF/Finish/raw cleanup/join proof. The relay keeps its exact unqueued pending event/allocation. A source already successfully finished is not relabelled failed by a later abort intent or unrelated metadata error. Failed raw startup keeps both source Runtime and original raw startup owner until independent cleanup, then explicit parser close and original join.

`source_kind()` distinguishes `OwnedPty` from `ExternalBytes`. External views reject Claim/user input/control and process resize, discard parser replies/clipboard/live VT metadata effects, and expose only checked observer presentation. Existing external constructors install no activity sink. `start_external_with_hooks` and `start_external_with_policy_and_hooks` opt into the same single owner sink for accepted display bytes only, including final decoder flush. Supply one unbound publication-gated sink from run startup and bind the existing shared Service activity book around trusted Show publication. Runtime performs no Session write, history touch or policy inference. Zero decoded display emits no output callback, and Observe/Frame/Recover/replay never re-touches. Raw stdin stays with AutomationRuns; source Finish is not a raw exit callback. Only independently confirmed raw exit invokes the Service's existing exit/TTL policy. `ResizeExternal` changes passive layout, never the upstream raw process. Observer detach removes only that presentation, not the run's parser. An unfinished external source rejects generic Close/RetryClose so host shutdown cannot accidentally retire its parser before draining raw output. Start deferred raw stop, keep pumping/retrying the exact pending chunk through both EOFs, enqueue ordered Finish, and only then retire the source after its finish barrier. Waiting for raw-byte observer Exited is not required for process cleanup, because that delivery may be credit-blocked. External `Phase::Closed`/`Exited`/finish is never raw-process exit or cleanup proof. AutomationRuns retains the actual raw owner and alone controls explicit stop/app shutdown. Startup failure or failed raw cleanup must retain the corresponding source/raw owner; Linux/macOS raw-process gates are unchanged.

## Live source hooks and metadata

`Runtime::start_with_hooks` accepts `RuntimeHooks { live_output: Option<Arc<dyn LiveOutputSink>> }`. Custom grid policies use `start_with_limits_and_hooks`. The sink receives identity, source sequence, borrowed bytes and `std::time::Instant` after each accepted live PTY feed, regardless of controller presence, event credit or observers. Parser-generated PTY input replies, replay, history, recovery and presentation reads never call it. Runtime stores no activity policy or additional raw-byte cache.

The optional default `LiveOutputSink::before_input(identity, request_id, kind, encoded, at)` runs only after nonempty encoding/length validation and before the writer. This lets the service mark anticipated echo using its already-registered admission context before output can race the confirmed reply. It does not prove write success; only the later receipt gates acceptance/CAS. Parser-generated replies bypass both input hooks and receipts. Consumers register bounded request context before submission and remove it on every reply/error/close.

The service supplies its existing shared activity policy and one clock anchor. A sink must be bounded, non-reentrant, do no I/O/Host calls and retain no raw bytes. Failure disables only that sink and is reported by `live_output_status()`, not by killing the PTY. The runtime does not reinterpret query/escape output or change legacy activity semantics.

`Runtime::metadata()` returns the latest immutable `Arc<RuntimeMetadata>` without draining it. Title and CWD URI are volatile application metadata, never a user rename, saved command or file permission. Bell/rejection counters are cumulative for this generation so coalescing cannot lose an unseen bell. Consumers establish a baseline on attachment and apply explicit live notification policy, rather than ringing historical bells. The public PWD callback supports several protocols, so this API does not claim OSC-7 provenance. Foreign file hosts stay untrusted URI text; no path is opened automatically.

## Trusted target-only program environment

`PtyConfig` and its user environment remain unchanged. `TrustedProgramLease` is an in-process bootstrap interface with a held verified program path and revalidation, not a Serde/request capability. `TrustedProgramEnv::ssh_askpass` retains target and askpass executable leases plus held native file identities, with an opaque redacted `AskpassBroker`. The only six carrier names are SSH_ASKPASS, fixed SSH_ASKPASS_REQUIRE/DISPLAY, and the three exact SHELLFOX_SSH_ASKPASS broker fields. No password/key passphrase belongs in them.

`PtySession::spawn_program` and `Runtime::start_program_with_hooks` are additive overloads. They require an explicit matching program, no shell profile, no conflicting carrier keys in user env, and preserve the same owner/parser/activity hooks. Program/helper leases survive until confirmed cleanup. A separate nonce-named startup pipe authenticates the exact supervisor and parent; it carries bounded private data outside argv/env. The supervisor's environment remains ordinary isolation only. It applies the finite carrier solely to the target Command after binding/file-ID checks, before target spawn. There is no global environment mutation, generic reserved-name map or new shell/elevation/WSL authority. TERM/COLORTERM and all existing protected user names stay isolation-controlled. Existing non-Windows native launch gates remain in force.

## Stamped controller epochs

`RecoverStamped` opts a real controller lease into atomic recovery/layout fencing. Exact `ControllerLayoutAck` consumption gates subsequent delivery and interactive side effects. `MouseStamped` validates captured geometry before owner encoding; `InteractiveBytes` preserves binary input. `ReleaseControl` and ordered `ControllerRevoked` retire only the real lease without stopping its PTY. V1 epochs and Observer APIs retain their behavior. See [the compiled producer API and tests](docs/controller-stamps.md). Runtime adds no share or metadata authority.

## Sealed initial launch facts

`Runtime::launch_privilege_facts()` reports descriptive Normal/Elevated/Unknown, fixed factory purpose, evidence basis/stage, and checked Windows token elevation/type/integrity/UIAccess. It never grants sharing, peer permission, process control or an all-future-session privilege promise. Missing/unbound/unsupported/uncertain evidence stays Unknown; `SourceKind`, PID, path, profile/elevation intent and output markers are not substitutes. In particular, a standard source may inherit an administrator host token and must not be labelled non-elevated by default. Normal means a complete consistent sampled non-elevated primary token below High integrity with UIAccess off, not absence of administrator membership or every possible security privilege.

The PTY factory captures on the authenticated pinned actual-child handle/birth/exact Job before public READY. The approved standard raw factory captures the original supervisor after Job assignment/before GO, attesting its fixed ordinary CreateProcess primary-token inheritance only after successful READY. Old unbound raw/PTY `spawn` overloads expose no receipt. Failed public startup exposes no receipt, even when its original controller must remain reachable for cleanup. Capture borrows original handles and closes TOKEN_QUERY immediately; sealed receipts retain no additional Job/process/token handles and cannot extend kill-on-close ownership.

An external source takes its private non-clone launch binding once, before `RawProcess::spawn_with_launch_binding`; one-shot raw evidence binds only to that exact Runtime/generation and the expected factory purpose. There is no enum setter/Serde capability. Preserve this opaque receipt with a published parser after RPC retirement, without retaining OS handles. ShareGrant and current peer permission remain separate and default-denied when absent. See [the evidence boundary](docs/launch-evidence-boundary.md) for scope and native gates. Mapping-unit tests do not claim native elevated/UAC acceptance.

## Owned process inspection

`request_inspection()` returns an `InspectionTicket`, or a typed `Pending`/availability error. `poll_inspection(ticket)` never waits for native collection. One request and one result may exist per runtime. A separate read-only worker collects evidence without holding terminal/parser, service, or command/event-channel locks. Closing or dropping the generation clears pending raw results; mismatched-generation tickets cannot consume them.

On Windows the terminal crate creates a private, local-only startup pipe before GO. It authenticates the connecting process against the exact original supervisor handle, native birth and Job. The supervisor publishes the birth of its original `std::process::Child` while retaining that handle. The parent opens a query-only child handle, checks its exact birth and membership in its own Job, and acknowledges it before READY. That child is the logical local command root, not the waiting supervisor or ConPTY. Process text is read only later on the inspection worker.

The capability enumerates only its retained Job, opens read-only candidate handles, and proves Job membership plus native birth before reading executable/argv. Evidence is bounded to 20000 rows, 64 KiB fields and an 8 MiB total budget including reserved row and argument storage. A bounded Job list or raw-data budget truncation returns partial evidence with `complete: false`, never a falsely fresh/healthy full snapshot. Sensitive evidence types intentionally implement neither `Debug` nor serialization. They must remain transient and must not be logged or persisted by adapters.

Local `wsl.exe` or `ssh.exe` launch evidence is not proof of a guest/remote shell tree. Linux/Darwin and guest/remote inspection remain unsupported until their authenticated guardian/read capabilities and native acceptance are wired. There is no global process scan or numeric-PID control fallback.

## Controlled checks

`cargo test -p shellfox-runtime --all-targets` includes pure delivery regressions and controlled Windows PTY integration tests using the crate's own supervisor-capable fixture executable. All scratch directories are under the workspace `tmp/` and removed after confirmed cleanup.

For a headless executable check, create an absolute isolated scratch directory under the workspace `tmp/`, then run:

```text
cargo run -p shellfox-runtime --bin shellfox-runtime-fixture -- --headless-check <absolute scratch directory>
```

The fixture runs only a fixed child command through the shared runtime. It is not the production CLI or a network service. Controlled activity modes include `--child-flood-on-input`, `--child-idle-escapes-repeat` and `--child-visibility-escapes-repeat`. The row-alternating mode can make ConPTY emit real CR/LF, which remains legacy-meaningful output. Its name is not a promise of quiet classification. The visibility-only mode changes hide/show every 100 ms at a fixed position. Native tests must classify the bytes actually delivered; pure cursor policy tests do not establish native PTY behavior. Fixed-fixture diagnostics report only bounded coarse counts, never production raw data. Desktop/headless host adapters use the same `Runtime` API; this crate does not expose local PTY launch to mobile clients.
