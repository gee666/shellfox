# Retained Go transport

This crate adapts the existing Go helper. It does not rewrite Tailscale or decide host permissions. `shellfox-protocol` owns `OutboundTransport`, `AuthenticatedPeerId`, `Endpoint`, `RequestLimits` and `TransportError`. Both this crate and the shared client use those definitions. Despite its historical name, `AuthenticatedPeerId` validates a destination string only. It is not proof of authentication or approval.

## Desktop and headless

Enable `helper`. Construct `VerifiedHelper` from an explicit absolute executable path and its independently verified SHA-256. The crate checks the digest before every spawn. If a resource manager owns the artifact bundle/cache lease, attach it with `VerifiedHelper::with_resource_guard(Arc<dyn Send + Sync>)`. Every spawned original child retains that guard, including offline ownership, probe/start rollback and detached cleanup. Keep the executable and its parent directories immutable to untrusted writers. A digest check cannot prevent an executable replacement between verification and process creation.

For persistent state, call `IsolatedStateDirectory::create_new_private(path, &verifier).await` once beneath an already-private app-owned parent. On restart, call `open_existing(path, &verifier).await` with that same fixed configured path. The synchronous `create_new` remains for newly created isolated fixtures and also writes provenance, but persistent Windows callers must use the verified constructor to protect the marker DACL before starting a node. No constructor overwrites an existing directory.

The marker contains a strict version, kind and SHA-256 of the canonical fixed path. Reopen bounds it at 256 bytes, pins directory/marker handles with no-follow checks, requires a single-link current-user private marker and validates through the verified permission helper. Reopen never repairs ACLs, migrates marker versions, reads node credential bytes, searches installed state or adopts an unmarked directory. A marker copied to another path refuses. `StateUnmarked` and `StateMarkerInvalid` report refusal without logging credentials. Retain a clone during a process lifetime, or reopen the same private root across restarts. This proves provenance and permissions, not node liveness or an exclusive node lease. Existing Go ownership/state locking remains responsible for exclusivity. The caller owns eventual deletion after shutdown.

`HelperConfig` requires that directory, hostname, loopback backend origin, and two different caller-generated secrets. `Secret::new` validates printable 32 to 256 byte tokens. Generate unpredictable tokens with the platform CSPRNG. Neither the crate nor its tests use a production default. `HelperTransport::start` probes protocol version 1, launches the retained helper and sends `start` without an auth key. Calling `start` can contact Tailscale coordination. It is never done automatically by these tests. `login` is a separate, explicit action. `login(None)` requests interactive enrollment.

The executable methods are `probe`, `start`, `status`, `peers`, `login`, `logout`, `subscribe_status` and `shutdown`. NDJSON commands are serialized with at most one pending command. Concurrent commands fail with `HelperError::Busy`. Status events use a latest-value watch channel. Command lines fit Go's 64 KiB scanner, replies are bounded at 1 MiB, commands time out after 30 seconds, and malformed or mismatched replies fail closed. Stderr uses fixed scratch storage and is never logged or returned. `shutdown_confirmed` sends `stop` at most once, closes stdin and returns `HelperShutdown` only after the original child's OS exit is confirmed. Its `stop_acknowledged` field distinguishes a valid stop reply from a lost reply followed by confirmed exit. An ACK, EOF or Lost token alone is never exit proof. Timeouts/wait errors retain the same controller and state capability for retry; repeated confirmation is idempotent. `child_exit_confirmed` exposes the same original-child check. Compatibility `shutdown` wraps that barrier. Probe/start cancellation, rollback and adapter drop transfer unconfirmed ownership to a prestarted cleanup thread that retains the child and state until confirmation. No numeric PID reopen or unrelated-process cleanup is used.

`OutboundTransport::send` opens one fresh loopback connection to the helper's validated `127.0.0.1` proxy origin. It sends exactly one authenticated POST to `/proxy`. Destinations are stable peer IDs and the five v1 endpoints only, using the canonical protocol `Endpoint` variants. No URL, address, method or caller identity can be supplied. The full proxy envelope must fit 1 MiB, responses fit 8 MiB, deadlines clamp to 30 seconds, and cancellation closes the request socket. The HTTP decoder bounds headers, content lengths and chunks. It rejects ambiguous framing. There is no connection pooling, retry or redirect path. A failed mutation has an uncertain outcome and must not be replayed by a caller.

A valid HTTP response containing `APPROVAL_REQUIRED` or `ACCESS_DENIED` remains an unchanged application response. The shared client and host must implement their own approvals, rejection, revocation, view permissions and terminal-control rules. Transport status must never grant those permissions. Numeric HTTP rejection status, including 404, remains `TransportError::Rejected { status }`; error text or a business error never becomes HTTP404. Transport never falls back. The canonical shared client owns the narrowly allowed pre-pair v2-discovery fallback. The new Go source allowlist/status API requires matching rebuilt and pinned native artifacts; existing staged v1 artifacts were not changed or relabeled.

## Offline host utilities

`PermissionVerifier::{check,protect}` uses the existing `--private-permissions` mode on Windows with a 1 KiB output limit and an eight-second timeout. The boundary converts canonical Windows verbatim disk/UNC paths to ordinary drive/UNC paths without resolving links. It rejects device namespaces, GLOBALROOT, ADS, dot segments, trailing-dot/space aliases and DOS-device names. Invalid path forms return `HelperError::InvalidRequest`; the retained helper's unsafe-permissions result returns `HelperError::PermissionDenied`. `normalize_private_path` exposes the same conversion for trusted host callers. It requires exactly the success object, successful exit and empty stderr. On Linux and macOS, the Go mode is intentionally unsupported. Rust instead checks the opened descriptor's uid, kind, link count and mode with `NOFOLLOW`, matching the active Node policy. There is no permissive fallback when checks fail.

Native startup first allocates `OfflinePreparation::new(helper)` before any anchor permission helper or handshake. Call `retain_original_directories(Vec<File>)` with clones of ALL original ancestor handles before native work; append original newly-created directory handles before binding. Already-spawned controllers retain the SAME shared chain. Its borrowed `permission_verifier()` tracks originals in that same scope. Scoped protection of existing objects rejects before actual ownership. Build `BoundOwnershipRoot::from_held(path, SAME_FILE_CLONE)` from the caller's retained descriptor, then consume `bind_root`. Failure returns the original preparation and error through `BindRootFailure::into_parts`. Binding performs no IO or cleanup-owner recreation.

Borrow `OwnershipAttempt::acquire`. An occupied result carries sealed `NoOwnerProof` only after the original contender and every preparation child are waited and new admission is closed. Errors/cancellation retain a usable attempt. `into_acquired` hands over the same resources exactly once; `AcquireTransferFailure::into_parts` returns the original attempt and error. The acquired `HostOwnership::permission_verifier` borrows that same verifier for publication/cleanup. No root release/reacquire occurs. `OwnershipAttempt::root_lifetime` and `HostOwnership::root_lifetime` return an opaque clonable lifetime-only guard. The Host-owning object must retain it through SQLite close and deferred cleanup, not only a thread-local closure. It is not a path/authority token, rooted VFS, or Unix-confinement claim; Host/VFS integration remains separately gated.

`shutdown_confirmed` closes admissions under the same lock as spawn/registration, then terminates/waits original helpers. No-child and positively waited originals can seal clean; wait errors/timeouts retain exact resources for retry. Original std children are registered before Tokio pipe conversion or any await. `HostOwnership::shutdown_confirmed(&mut self)` uses that same scope. Lost tokens and EOF are health only, never exit proof. Compatibility `HostOwnership::acquire` also captures a no-follow held root and sends its exact expected identity; Service must instead bind its already-held original File. See [bound ownership](../../native/tailscale/OWNERSHIP.md) for exact native widths and helper arguments.

Unix/macOS privacy now checks ACL/inheritance on held descriptors. Any extended ACL, including benign deny-only entries, and unknown/unsupported replies refuse. Chmod alone never removes that limitation. The no-follow walk makes no privacy claim about common-home ancestors. macOS common-home inheritance is not verified natively yet. Windows base-root explicit-SD relative creation belongs to Service; existing occupied root/lock modes and DACLs are never repaired by the acquisition helper.

These utilities establish permissions and a kernel lock, not endpoint publication, private endpoint reads or an authenticated host RPC server. Their consumer must implement those separately.

## Mobile

Default features expose only the outbound adapter and protocol contracts. They compile without this crate's subprocess, sockets, state-directory or host-secret APIs. Implement `NativeOutbound::request` using the existing Go mobile `Request(peerId, path, body)` binding and wrap it with `NativeAdapter`. The native implementation must enforce limits before allocating a response, honor cancellation/deadlines while work is in flight, drop native work when its future drops, and prohibit redirects and POST replay. Rust checks JSON, size, deadline and cancellation before dispatch, and checks the returned bytes again. This is an injectable boundary, not completed Android/iOS bindings or device acceptance.

## Incoming host authentication

Enable `host-auth` to use `incoming::verify_peer`. Supply exactly one value of each signed header, the raw method/path, exact request body and current Unix milliseconds. Reject duplicate HTTP headers before calling it. Verification matches the existing Go and Node HMAC contract, including the original encoded peer header, body SHA-256 and 30-second skew. Successful verification identifies the helper-authenticated caller only. Apply host approval and revocation afterward. Mobile does not enable this feature.

## Offline checks

```sh
cargo test --locked --offline -p shellfox-transport --all-features
cargo test --locked --offline -p shellfox-transport --no-default-features
cargo clippy --locked --offline -p shellfox-transport --all-features --all-targets -- -D warnings
```

The `test-helper` feature builds an offline Rust fixture executable. Tests own its processes, use local loopback sockets only and remove their own scratch directories under root `tmp/`. The signing test uses the existing Node/Go digest vector in `native/tailscale/bridge_test.go`.

Ignored tests run an explicitly injected real helper in offline modes only. The persistent-state test also verifies protected marker creation, canonical-path reopen, opaque credential preservation and check-only rejection of unsafe marker ACLs/hardlinks. The ownership test exercises repeated original-child confirmation and lock reacquisition. It also checks directory/file paths returned by `std::fs::canonicalize`, including Windows verbatim prefixes, and verifies lock contention and reacquisition:

```sh
SHELLFOX_OFFLINE_HELPER=/absolute/path/to/verified/helper \
SHELLFOX_OFFLINE_HELPER_SHA256=verified-64-digit-sha256 \
cargo test --locked --offline -p shellfox-transport --all-features \
  --test offline real_retained_go_helper_offline_contract -- --ignored
```

Go is not needed for the Rust fixture tests. Building the real retained helper needs the pinned Go toolchain through `SHELLFOX_GO` or PATH. No test enrolls a node, opens a real tailnet connection or uses installed credentials. Real login, host/client integration, package and macOS/Linux/Android/iOS device acceptance remain separate checks.
