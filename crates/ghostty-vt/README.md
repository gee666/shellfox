# Shellfox Ghostty terminal wrapper

`Terminal` owns a real libghostty-vt 1.0.1 terminal, render state, key/mouse encoders and reply buffer. It has no GUI, PTY or mobile dependencies. The companion sys crate contains all Rust `unsafe` and a C adapter compiled against `<ghostty/vt.h>`. It does not include the internal `ghostty.h` or read packed cell bits. See [build prerequisites and provenance](../ghostty-vt-sys/README.md).

```rust
use shellfox_ghostty_vt::key::{KeyEvent, KeyModifiers, PhysicalKey};
use shellfox_ghostty_vt::Terminal;

let mut terminal = Terminal::new(80, 24)?;
terminal.feed(b"hello\x1b[6n")?;
let replies = terminal.drain_replies()?; // Write these once to the owning PTY.
let screen = terminal.render()?;        // Owned cells, never generates replies.
let enter = terminal.encode_key_event(&KeyEvent::press(PhysicalKey::Enter, KeyModifiers::NONE))?;
# Ok::<(), shellfox_ghostty_vt::Error>(())
```

Keep the terminal on one thread. It deliberately does not implement `Send` or `Sync`. Feed each output byte once, in order. Drain replies after feeding and resizing. The authoritative terminal's owner alone sends query replies to its PTY. A historical client mirror must not send replies generated by replay. Render data is copied before another native operation and remains valid after resize, another render or terminal destruction.

## Keys, paste and focus

All key input is `key::KeyEvent`, encoded by Ghostty's own encoder with the terminal's live modes: application cursor and keypad, kitty keyboard flags, modifyOtherKeys and Alt-sends-Escape. There is no other key table.

- `physical` is a public GhosttyKey (176 values, checked `TryFrom<u32>`).
- `text` is the layout text without Ctrl applied. C0, DEL and U+F700..U+F8FF are rejected. Committed IME text uses `KeyEvent::text` with an unidentified key.
- `modifiers` and `consumed_modifiers` take all ten GhosttyMods bits.
- `unshifted_codepoint` is the key's base character. `None` means unknown; NUL is rejected.

The serde form is camelCase, with `physical` and the codepoint as numbers. It is the same JSON the mobile platforms send.

`encode_paste` treats every paste as a user action: multi-line text is not refused, CRLF becomes one line break, and Ghostty replaces ESC/NUL/DEL and frames the text per mode 2004. `encode_focus` is empty unless the application enabled mode 1004.

Encoding returns one owned vector, bounded at 1 MiB. Hosts apply their own write cap.

## Mouse, selection, links and colors

`mouse_tracking()` reports whether the application requests mouse events.
`encode_mouse(&MouseEvent, MouseGeometry)` uses the public Ghostty encoder and
the terminal's current modes. Coordinates are content-local pixels; subtract
UI padding before calling. Cell dimensions are nonzero integer pixels. Send
wheel steps as presses of `WheelUp`, `WheelDown`, `WheelLeft` or `WheelRight`.
The UI accumulates fractional wheel motion. An empty encoded result means the
current mode does not report that event. Buttons `Ten` and `Eleven` have public
identities but no wire encoding in vt-1.0.1. Motion is not deduplicated here.

`set_selection(Some(Selection::Range { start, end, rectangle }))` selects an
inclusive range of zero-based viewport cells. Reversed ranges are valid. `Word`,
`Line` and `All` use Ghostty's selection rules; `All` includes scrollback.
`set_selection(None)` clears the selection. Ghostty tracks installed endpoints
across edits/reflow and can clear them, including on an application screen
switch. `Cell::selected` reports the current render state.

`copy_selection()` returns owned plain UTF-8 text or `None` without an active
selection. Ghostty trims trailing whitespace and joins soft-wrapped lines.
No raw grid reference survives a call; copy reconstructs fresh references from
the terminal-owned selection. This method does not access the OS clipboard.

`Cell::has_hyperlink` flags OSC 8 metadata. `hyperlink_at(ViewportPoint)` copies
the URI on demand, without launching it or guessing links from screen text.
Treat the result as untrusted. The host/UI must enforce scheme, control-character,
path, authorization and user-intent policies before opening anything.
The public API exposes the URI, not the OSC 8 link ID or arbitrary parameters.

`set_colors(&TerminalColors)` sets real parser defaults for foreground,
background, cursor and the 256-entry palette through public setters. A `None`
palette restores Ghostty's defaults. Existing default/indexed-color cells use
new defaults; explicit truecolor remains unchanged. Application OSC overrides
remain authoritative until reset. These are not renderer-only substitutions.

## Volatile process metadata

`take_metadata()` returns an owned `TerminalMetadata` snapshot or `None` without
pending updates. It coalesces the latest title and `cwd_uri`, a monotonic version,
and bell/rejection counts since the previous successful take. Rendering and
presentation reads do not drain metadata. Fallible copies complete before the
C-owned pending state is acknowledged.

Titles have C0/C1 controls removed, Unicode whitespace trimmed and at most 200
UTF-16 units. Raw callback titles above 4 KiB or with invalid UTF-8 are rejected.
CWD candidates are at most 32767 UTF-8 bytes and must be file-URI-shaped, without
credentials, ports, query/fragment or raw/percent-decoded controls. Foreign hosts
remain explicit. Invalid callback values retain the last accepted value. Both
counters cap at 65535; bells have an explicit saturation flag. Full reset clears
title/CWD, while soft reset preserves them.

These are untrusted, volatile process data, not saved user titles, command logs,
filesystem authority or permission to run effects. The owner must enforce host,
profile and path policy before using a directory. A historical mirror must not
publish replayed metadata as live authority. The public PWD callback does not
identify the originating OSC protocol. Ghostty can also reject an oversized OSC
before invoking any callback, so `rejected_updates` cannot count those events.

## Recovery inspection

`format_vt(extras, max_bytes)` copies the public formatter's active screen as
VT bytes. Extras are restricted to the public `0xFFF` mask. Trimming and
unwrapping are disabled. The caller's output limit is enforced without
truncation, with an additional hard limit of `MAX_FORMAT_BYTES`, 16 MiB.
It does not drain replies, alter the source screen or complete its parser.

`continuation()` copies the public replay-safe unfinished parser/UTF-8 suffix.
Every terminal enables continuation tracking before its first feed, with a
64 KiB limit. The bytes are not necessarily valid standalone UTF-8. If the
current continuation exceeded the tracking limit, the method reports an error
rather than pretending the parser is at ground. Tracking can recover after
later input returns to ground or provides a fresh replay start.

`recovery_info()` reads columns, rows, active-screen identity, pending-wrap
state and the active screen's scrollback-row count. These APIs do not make a
full-state snapshot. The public formatter cannot export the inactive screen or
saved cursors. A recovery protocol must negotiate those limits and suppress
query/effect authority in replaying mirrors. Never advertise full-state recovery
from these bytes alone.

## Bounds and failure behavior

- At most 1 MiB of VT input per `feed` call. Split larger reads without changing their order.
- Nonzero dimensions and at most 1,048,576 cells.
- At most 1 MiB of pending query replies, one cell's UTF-8, encoded input, copied selection or hyperlink URI.
- Mouse geometry and absolute pixel coordinates are at most 1 billion per axis, within the native signed pixel conversion range. NaN, infinity, zero cell sizes and multiplication overflow are rejected.
- At most 16 MiB of copied cell text per render.
- Reply overflow or callback allocation failure permanently poisons the terminal. The callback discards its pending prefix. Every operation then returns the sticky error, even with malformed arguments. Stop the owning PTY rather than resume after lost replies.
- A copy/input limit rejection does not itself poison the terminal. Nothing has been sent or lost, so the caller can reduce the request and retry.

Errors preserve native numeric codes, including unsupported operations. Fallible Rust allocation requests use `try_reserve`; native buffer allocations check failure. Upstream `ghostty_terminal_vt_write` returns `void`, so this wrapper cannot expose parser failures that upstream does not report. The wrapper's limits do not replace upstream's internal resource limits.

No binary snapshots or recovery protocol are implemented in this wrapper. These owned screen cells are render inspection data, not a restorable terminal snapshot. Image placement, search, selection gesture helpers and graphics are not exposed yet. The UI must not advertise these as supported merely because libghostty-vt implements them.

## Checks

```sh
cargo test --locked -p shellfox-ghostty-vt
cargo clippy --locked -p shellfox-ghostty-vt -p shellfox-ghostty-vt-sys --all-targets -- -D warnings
```

On this Windows x86_64 worktree, Rust 1.97.1 MSVC compiled the C adapter, linked the official GNU import library, and loaded its DLL. The wrapper integration tests cover fragmented UTF-8/ANSI, grapheme clusters and wide cells, truecolor/styles/theme changes and OSC resets, render ownership, alternate screen, resize/cursor visibility, one-time DSR replies, Ghostty key encoding across cursor, keypad and kitty modes, paste framing, mouse tracking/formats/buttons/wheel/modifiers/pixel bounds/outside release, Unicode/word/line/rectangular/all selection, bounded copying, OSC 8 metadata, VT formatter replay and source immutability, unfinished UTF-8/CSI continuation and its overflow recovery, public recovery indicators, malformed output and sticky query-overflow failures across every operation. One optional DOM differential test is ignored by default. Compile-fail doctests enforce terminal and presentation-view thread confinement. This does not verify macOS, Linux, Android, iOS or Windows arm64 runtime behavior.
