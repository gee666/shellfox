## Existing TypeScript file-write assertion repro

Juan reproduced the previously reported failure in `src/main/files/service.test.ts`, in `serializes competing views and checks authorization again before an atomic save`. This is separate from helper provisioning and from the new Rust files implementation.

Source inspection confirms `FileService.save` in `src/main/files/service.ts` awaits `resolveFileTarget` and `realpath` before adding the write to the per-canonical-path queue. Two calls invoked in array order can reach that queue in the opposite order.

The reported repro has the expected safety outcomes:

- Exactly one competing write succeeds.
- The other write returns `FILE_CONFLICT` for the stale revision.
- The subsequent unauthorized write returns `ACCESS_DENIED`.
- The persisted content may be `second`, while the existing test unconditionally expects `first`.

That final invocation-order assertion is flaky under the observed queue-admission behavior. It is not evidence that the unauthorized write committed. It also does not prove all file authorization and staging races are safe. No production/test code fix was made, no blanket baseline-pass claim is warranted, and the earlier unexpected Vitest worker exit remains unverified.

Carry the actual invariants into Rust files tests: one winner, stale-write conflict, authorization checked before atomic replacement, and no unauthorized mutation. Do not silently introduce an invocation-order guarantee unless the API explicitly requires it. Any baseline test correction needs its own reviewed change and focused verification.

## Public Ghostty ABI recovery blocker

The integration lead reports a real full-state recovery limitation in public `libghostty-vt` 1.0.1. The formatter exports the active screen, not inactive buffers or saved cursors. Pending-wrap reconstruction can itself replace a saved cursor. Mode-stack fidelity is also not established. This blocks full-state recovery acceptance even when the active screen looks correct.

Maurice owns implementation and tests for limited `FormattedActiveBufferV1`; Heather owns bounded public formatter/continuation/mode exports. The runtime formatter helper now uses the `FormattedActiveBufferV1` name. Final capability negotiation/adapter wiring is not inferred from helper functions or the presence of ANSI bytes. The limited capability is a formatted active-buffer projection, never `FullState` or a full Ghostty snapshot.

Inspected source evidence:

- `shellfox-runtime/src/recovery.rs` bounds recovery at 4 MiB, reads continuation before formatting and appends it last. The actual `AnsiRecoveryCapability` enum now offers `VisibleScreen` and `FormattedActiveBufferV1`, not FullState. Mirrors must suppress replies/clipboard effects; source query replies must not be drained or replayed.
- Maurice now reports 12/12 recovery tests executed and passed against real Ghostty and legacy xterm, including UTF-8/CSI continuation barriers. The handoff also reports three executable FullState counterexamples for saved-cursor, inactive-buffer and Kitty-mode gaps. These document unsupported fidelity, not successful full-state restore; do not add them to the 12-test count without an explicit breakdown. Exact commands were not supplied and documentation did not rerun them.
- `ghostty-vt/src/recovery.rs` and sys recovery code use public formatter/continuation/getter APIs with byte limits and explicit unavailable/overflow errors. The wrapper documents the missing state. Formatter extras do not export a hidden inactive buffer.

Decision: retain the existing Node ANSI-compatible recovery implementation until equivalent new-protocol/full-state behavior is proved. A full replacement requires an adequate upstream public API or a separately negotiated/versioned Ghostty snapshot protocol plus tested legacy fallback. Do not send binary snapshots to legacy xterm/ordinary CLI clients. Do not use internal Ghostty ABI, unbounded transcript/replay storage or output persistence as a workaround. Explicitly reject unsupported fidelity rather than returning a silently downgraded payload.

Required acceptance includes both buffers across switching, saved cursor plus pending wrap and subsequent cursor restore, supported modes/stacks, parser continuation, history, resize/output sequence barriers and consumption ACKs. Assert no duplicate PTY replies or replayed clipboard effects. Limited-capability passes cannot mark these missing-state cases or the full application translation complete.
